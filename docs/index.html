Camera Degradation
Health Score

A lightweight ADAS experiment: controlled camera corruption → measurable health proxies → failure analysis → fallback decision.

T1 · Reproducible synthetic demo

Problem

Blur, glare and noise can make a forward camera unreliable. We ask whether the system can detect degraded input before trusting downstream perception.

Method

Inject Gaussian blur, glare and salt-and-pepper noise. Measure Laplacian variance, saturation, entropy and edge retention. YOLOv8n is an optional detector proxy.

Benchmark

No large dataset is required. The repository generates a deterministic road-like scene and five corrupted variants. Run python src/run_demo.py to produce CSV evidence and plots.

Truthfulness: health metrics are engineering proxies. Detector confidence is not mAP or recall.

Failure case

Strong glare defeats a blur-only monitor. A saturated region can lose important visual information while global edge energy remains elsewhere. Camera health therefore needs exposure/saturation evidence in addition to sharpness.

Engineering decision

Health < 0.40 for 3 consecutive frames → DEGRADED

Log camera/ISP metadata, down-weight camera evidence in fusion, and request a safer operating mode. Independent Radar/LiDAR evidence can support fallback when the vehicle architecture provides it.

0.40 and 3 frames are prototype choices, not validated production safety thresholds.
